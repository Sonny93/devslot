# Commands

Reference of the `ds` commands. `ds <command> --help` lists the options and the exit codes of each.

| Command | What it does |
| --- | --- |
| `ds doctor [--json]` | Reviews the project without starting or writing anything. Also reports the state of the worktree guard (see below). |
| `ds up` | Registers the checkout, writes the block, starts the services, then runs the `run` key (`--no-run`: services only). |
| `ds down` | Stops the services and keeps the data. |
| `ds run -- <command>` | Registers the checkout if needed and runs a command with the instance environment. |
| `ds env [--format sh\|json]` | Prints the environment of the instance. |
| `ds info [--json]` | Shows the name, slot, ports, URLs and services state of this checkout's instance. |
| `ds ls [--json]` | Lists every instance of the machine with its ports and whether its services run, then the worktrees Claude Code asked to remove that are still there, with the reason. On a narrow terminal the PATH column wraps: `--json` gives the same list without it. |
| `ds ensure` | Registers the checkout and writes its block without starting anything (what the hook runs). Does nothing in a main checkout covered by the worktree guard. |
| `ds reset [service]` | Deletes the data of the instance, or of one service, and starts the services again. |
| `ds rm [--yes]` | Deletes the instance's data, removes the block and opts the checkout out. |
| `ds prune [--yes]` | Deletes the data of the instances whose folder is gone and forgets them, and the session leases whose session ended (see [Worktrees in use](worktrees.md#worktrees-in-use-linux-only)). |
| `ds worktree land [--onto <branch>]` | Run in a linked worktree: fast-forwards the main checkout's branch onto the worktree's branch. Never pushes. |
| `ds worktree rm <name\|path> [--yes] [--force]` | Shows what would be lost, refuses a worktree in use by another session or program unless `--force`, then stops the instance's processes, removes a linked worktree, deletes its data, forgets its instance and deletes its branch when that is merged. |
| `ds hook <event>` | Called by the Claude Code plugin: `worktree-create`, `worktree-remove`, `pre-tool-use`, `session-start`. Not meant to be run by hand. |

**`ds worktree land [--onto <branch>]`.** Run from a linked worktree, after the work is committed. It fast-forwards the branch checked out in the main checkout onto the worktree's branch, by running `git merge --ff-only` in the main checkout. The target is the base recorded when `ds hook worktree-create` created the branch (in `git config branch.<name>.devslotBase`, only when the base was a branch), or `--onto <branch>`, which wins. A branch created without a recorded base, or reused, needs `--onto`. Because the merge runs in the main checkout, it updates that checkout's files and runs the repository's `post-merge` hook. It never rebases, forces, stashes, resets or pushes. It refuses, changing nothing, when:

- the folder is not in a git repository, is the main checkout, or is on a detached `HEAD`;
- no base is recorded and there is no `--onto`;
- the worktree has uncommitted changes to tracked files (untracked files only give a warning: `ds: warning: <n> untracked file(s) in the worktree are not landed`);
- the main checkout is not on the target branch, or is in the middle of a merge, rebase, cherry-pick, revert or bisect;
- the base moved, that is the target is not an ancestor of the worktree's `HEAD`: run `git rebase <target>` in the worktree, resolve the conflicts, commit, then run `ds worktree land` again;
- the branch adds a path that already exists in the main checkout, untracked or ignored, or a path below a file or symbolic link of the main checkout that its index does not hold as a file (the message lists up to ten);
- git refuses the fast-forward.

Refusals print `ds: error: <reason>` on stderr and exit 1. On success it prints `<target> moved from <old> to <new> (<n> commit(s))`, or `nothing to land: this branch is already at <target>` (exit 0). Exit codes: 0 success or nothing to land, 1 a refusal, 2 the tool itself failed (git unavailable or timed out) or invalid usage. See [Worktrees](worktrees.md#land-the-work-on-the-main-checkout).

**Worktree guard in `ds doctor` and `ds ensure`.** When `[worktrees] require` is not empty, `ds doctor` adds a `worktree_guard` info finding that says whether the guard is active for the checkout, covers a linked worktree, is switched off by `devslot.local.toml`, or does not cover it. It warns (`worktree_require_ignored`) when `devslot.toml`, or a tracked `devslot.local.toml`, sets `[worktrees] require`, since only an untracked `devslot.local.toml` is read. It informs (`worktree_guard_registered`) when a covered main checkout was registered before the guard covered it. `ds ensure`, and so the hook, does not register a covered main checkout: it exits 0 and does nothing. A main checkout that is already registered is left as it is, slot and `.env` block included, and no longer updated.

**`ds worktree rm <name|path>`.** A name (letters, digits, `.`, `_`, `-`) is the worktree `<[worktrees] root>/<repo>/<name>` of the repository of the current folder; an argument that contains `/` or starts with `.` is a path, and any linked worktree root will do (never the main checkout or a subfolder). Before acting it prints the path, the branch, the instance (or "not registered"), the processes it would stop and the other processes found there, the number of uncommitted changes, and the number of commits found nowhere else (reachable from the worktree's `HEAD` only; the branch counts as a place only when it is kept). Ignored files (`.env`, local databases, uploads) are deleted with the folder, and the preview says so. It then asks like `ds rm` (a terminal, or `--yes`). A worktree with uncommitted changes or commits found nowhere else, or in use by another session or program (the preview shows an `In use` line that lists those processes and the live leases of other Claude Code sessions, and refuses before asking; see [Worktrees in use](worktrees.md#worktrees-in-use-linux-only)), also needs `--force` (without a terminal and without `--yes`, the refusal names `--force --yes` at once); the changes and commits are counted again after the processes are stopped, right before `git worktree remove`, and the removal is refused (nothing deleted) when either count grew. When another creation or removal of the same worktree is running, it waits up to 10 s after the confirmation, then refuses; it also refuses when the worktree changed since the preview. A locked worktree is refused (`git worktree unlock` first) before anything is stopped, deleted or forgotten. After the data is deleted and the instance forgotten, the branch is deleted when it is named like the worktree folder and `git merge-base --is-ancestor` confirms it is merged into the `HEAD` of the main checkout; otherwise it is kept and ds says so. The hook runs the same removal without the preview and the gates, because Claude Code decides when a session ends, except for two checks it applies without any way to skip them: the use check above, and a check for unsaved work. When uncommitted changes or commits found nowhere else exist, the hook refuses (exit 1) before stopping anything, counts again before `git worktree remove`, and says `<path> has <n> uncommitted change(s) and <m> commit(s) found nowhere else; nothing was deleted. Run ds worktree rm <path> from a terminal to review the work and remove the worktree anyway.` The checks run under a 150 s budget; a count that cannot finish in time also refuses the removal. `ds ls` lists the kept worktree with the reason `it holds unsaved work`.

Exit codes: 0 success, 1 a refusal or an error in the project, 2 the tool itself failed or invalid usage. `ds run`, and `ds up` with a `run` key, exit with the code of the command they run (126 when it cannot be executed, 127 when it is not found). `--help` of each command lists its codes; `ds --help` also lists the global `--color` option and the environment variables ds reads (`NO_COLOR`, `DEVSLOT_DOCKER`, `XDG_CONFIG_HOME`, `XDG_STATE_HOME`). `ds ls --json` and `ds info --json` are versioned contracts.
